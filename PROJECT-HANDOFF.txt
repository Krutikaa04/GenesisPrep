1. GOAL
--------------------------------------------------------------------------------
Build ./salvage <input_dir> <output_dir>: an OFFLINE command-line tool that
identifies legacy binary files from their bytes, decodes what is provably
intact, recovers as much as possible from damaged files, and reports honestly
what was lost. For every input file it writes <output_dir>/<input name>.json
(example: s01.dat.json) plus report.json. Always exit code 0. No network, no
AI/LLM calls at runtime. Python 3 standard library only.

Judging is on hidden files produced by the SAME generators as the 30 sample
files in samples/official/. Records are matched on a key (id / sample / cell /
name / ...) and graded on their fields, plus the file status and the damage
"kind". Accuracy and honesty matter more than breadth. A guessed value that
looks right but is unverified LOSES points; mark it verified:false instead.

2. OUTPUT CONTRACT (authoritative: samples/official/OUTPUT-CONTRACT.md)
--------------------------------------------------------------------------------
Per-file JSON (exactly these top-level keys):
  {"source_file": "s01.dat", "format": "LIBRA-98", "status": "ok",
   "metadata": {}, "records": [], "damage": [
      {"kind": "crc_mismatch", "offset": 123, "detail": "...", "lossy": true}]}

status       ok | partial | unsupported | unrecognized | failed
  ok = nothing lost; partial = some data lost OR unverified; unsupported =
  recognised but cannot decode (e.g. encrypted); unrecognized = unknown format;
  failed = recognised but unreadable.
damage.kind  ONLY these: truncated, crc_mismatch, checksum_mismatch,
  bad_length, unparsed_bytes, count_mismatch, invalid_value, oob_pointer,
  index_missing, header_checksum, encrypted, unknown_record
  (deadbits/model.py raises if you use anything else)
format       LIBRA-98, LABLOG, VAULT, WKS, WPD, BRAVO, CVT, EBCDIC-DUMP, WAD,
  PAK, UNKNOWN
A recovered-but-unverified record carries "verified": false and/or
"issues": [kinds].
Input listing is NON-recursive; directories are skipped.
report.json: {"tool_version", "files": [{"file","format","status","records":N,
  "damage":N}], "totals": {status: count}}.
Graded record fields per format (see OUTPUT-CONTRACT.md for the full table):
  LIBRA-98: id,title,author,year,price_cents,copies,isbn,checked_out,deleted,
            reference_only,due_date
  LABLOG:   sample,time_ms,values[] ; metadata: instrument,sample_interval_ms,
            channels[{index,unit}],start_time_utc,declared_block_count,events[]
  VAULT:    id,name,type,size,sha256,compressed,text|width/height
  WKS:      cell,row,col,type,value,alignment,number_format,iso_date,
            cached_value,formula_raw_hex ; metadata: version_code,
            declared_range,column_widths
  WPD:      index,type(paragraph|page_break),text
  BRAVO:    index,text   (metadata.format_runs is a bonus)
  CVT:      slot,text ; metadata: name,structure,geos_type,modified,
            class_name,author,description,declared_blocks
  EBCDIC:   student_id,name,dob,gpa,credits,status,balance ; metadata: title,
            run_date,trailer_count,trailer_credits_total
  WAD/PAK:  name,offset,size,sha256

3. CURRENT STATE (all of this already works and is tested)
--------------------------------------------------------------------------------
- All 10 formats are implemented and decode every file in samples/official.
- 7/7 organizer reference outputs match (python tools/compare_expected.py).
- 57 unit tests pass (python -m unittest discover -s tests -p "test_*.py"):
  reference tests, a mutation suite (truncate at every offset, byte flips,
  extreme values, zeroed blocks, junk), CLI contract tests, per-format tests.
- Docker image builds offline and gives byte-identical output to a native run.
- Adapters are AUTO-DISCOVERED: dropping a new module into deadbits/formats/
  registers it. Nobody edits a shared registry.

Status of the 30 sample files (what our tool outputs today):
  s01-s03 LIBRA ok | s04 LIBRA partial (truncated, partial record id 1040)
  s05,s06 LABLOG ok | s07 LABLOG partial (one block CRC mismatch, deliberate)
  s08-s10 VAULT ok  | s11 WKS ok | s12 WKS partial (unknown opcode 0xFA)
  s13 WKS partial (truncated) | s14 WPD ok | s15 WPD partial (truncated)
  s16,s17 BRAVO ok  | s18,s19 CVT ok | s20,s21 EBCDIC ok | s22 EBCDIC partial
  s23 WAD ok | s24 PAK ok | s25,s26,s27,s28,s30 unrecognized
  s29 LIBRA failed (header truncated: "LB98" + 3 bytes)

Layout knowledge per format (what is CONFIRMED vs ASSUMED) is in
FORMAT-SPEC.md; what was tried, including failed hypotheses, is in
FIELD-LOG.md. READ BOTH before editing a decoder.

Key design rules already in the code:
- detect(data)->0..1 needs structural proof (signature + coherent header or
  checksum). decode(data, name)->Result never raises on bad input.
- Records are decoded one at a time; a bad record is isolated and the scan
  resynchronises. Never invent a value: omit it / null it and flag it.
- Checksums: LIBRA record = sum8(flags..before chk), trailer = sum16 of all
  bytes before "END!". LABLOG header+blocks = CRC-16/CCITT-FALSE. Others have
  no checksums (stated limitation).
- Damage offsets are clamped to the file size by Result.to_dict().
- Output JSON is LF-only UTF-8, sorted by file name, deterministic.

5. GIT WORKFLOW (3 people, 3 branches, merge to master when finished)
--------------------------------------------------------------------------------
One-time (project lead, M3, runs this ONCE and pushes). The repository
(github.com/Krutikaa04/GenesisPrep) already has a "master" branch with one
initial commit; "master" is the integration branch. (If the team prefers
"main", rename the branch on GitHub once and substitute it in these commands.)

auto-discovery, per-format tests, this handoff file), so first:
  git checkout master
  git add -A && git commit -m "Auto-discovered adapters, per-format tests, handoff"
  git push origin master             # then M1 and M2 run: git pull origin master

Branches (one long-lived branch per member, short sub-branches optional):
  m1/gate-instruments   M1
  m2/containers         M2
  m3/archives-platform  M3

Daily loop for every member:
  git fetch origin && git rebase origin/master      # stay current, resolve early
  ...work on YOUR files only...
  python -m unittest discover -s tests -p "test_*.py"   # must be green
  python tools/compare_expected.py                       # must be 7/7
  git add -A && git commit -m "<area>: <what>"           # small commits
  git push origin <your-branch>

Merging to master (only when your task list item is DONE and green):
  1. rebase on origin/master, re-run both commands above
  2. open a pull request <your-branch> -> master; another member reviews
  3. squash/merge; M3 re-runs the full suite + Docker check on master
Never push directly to master. Never force-push master. If two members must edit
the same file (model.py, engine.py, cli.py, tests/helpers.py), tell M3 and let
M3 make the change.

Conflict-prone shared docs: FORMAT-SPEC.md and FIELD-LOG.md. Each member only
edits the section headed with their own format name, adding to it. If a merge
conflict appears there, keep BOTH sides.

8. RULES (apply to every member and every agent)
--------------------------------------------------------------------------------
 1. Python standard library only. No network access at runtime or in tests.
 2. Never edit samples/official/ (read-only fixtures).
 3. Never change the contract: key names, status words, damage kinds,
    file naming. deadbits/model.py is the single source - M3 changes it.
 4. Never invent data. Unreadable value -> omit/null + verified:false +
    issues. Wrong-but-plausible output is worse than missing output.
 5. A decoder must never raise on any bytes. Every length/offset/count read
    from the file is hostile: bound-check before slicing, looping, allocating.
 6. Keep detect() strict: a signature alone is not proof (except where the
    contract demands it, e.g. LIBRA header truncated -> failed).
 7. Change ONLY files you own (section 4). Cross-cutting need -> ask M3.
 8. Every behaviour change needs a test; every guess needs a line in
    FORMAT-SPEC.md marked "assumption"; every dead end goes in FIELD-LOG.md.
 9. Do not weaken or delete existing tests to make them pass. If a test is
    wrong, say why in the commit message.
10. Output must stay deterministic and LF-only UTF-8.
11. No unrelated refactors, no new dependencies, no GUI, no database.
